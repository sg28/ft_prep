# Python → JavaScript Translation Guide

You are translating one chapter of a Python coding-interview prep book into JavaScript.
Produce a faithful JavaScript version of the same chapter.

## General rules
1. Keep ALL sections, headings, problem statements, LeetCode/Wikipedia links, examples,
   explanations, complexity analyses, and exercise lists. Preserve structure, ordering,
   and problem numbering. Do not drop or invent problems.
2. Convert every Python code block (```python or ```python=) into a ```javascript block
   with idiomatic, modern, **runnable** ES2020+ JavaScript.
3. Adapt the PROSE too: wherever the text explains a Python-specific concept, rewrite it to
   describe the JavaScript equivalent. Replace mentions of Python features/modules with their
   JS counterparts. Keep the tone and educational intent.
4. Change "Python" to "JavaScript" in the chapter title where it appears.
5. Produce CORRECT code. If the original Python had an obvious bug, silently fix it so the JS
   works and preserves the intended behavior.
6. Keep external links (LeetCode/Wikipedia/docs) unchanged, except swap Python-docs links for
   MDN links when a sentence is specifically teaching a language feature and an MDN link fits
   naturally. When unsure, keep the original link or drop just the hyperlink but keep the text.

## Language conventions
- `print` → `console.log`. `assert a == b` → `console.assert(a === b)` (or a small `assert` helper).
- `True/False/None` → `true/false/null`; use `===`/`!==`.
- f-strings → template literals: `` `${x}` ``.
- snake_case identifiers → camelCase (JS convention).
- `len(x)` → `x.length`. `range(...)` → `for` loops.
- `enumerate` → `.entries()` or an index loop. `zip` → index loop / helper.
- `x ** y` stays `x ** y`. `a // b` → `Math.floor(a / b)` (use `Math.trunc` if negatives must
  round toward zero). Note JS `%` differs from Python for negatives; adjust if it matters.
- `divmod(a, b)` → `[Math.floor(a / b), a % b]`.
- `ord(c)` → `c.charCodeAt(0)`; `chr(n)` → `String.fromCharCode(n)`.

## Data structures
- list → Array. `append`→`push`, `pop()`→`pop()`, slicing→`slice`, `insert`→`splice`,
  list comprehensions → `map`/`filter`/`Array.from`.
- dict → `Map` for arbitrary/numeric keys (preferred), or a plain object for string keys.
  `d.get(k, default)` → `d.get(k) ?? default`; `k in d` → `d.has(k)` (Map) or `k in obj`.
- set → `Set`; `x in s` → `s.has(x)`; add→`s.add`. For union/intersection/difference,
  implement them explicitly (portable). You may MENTION the ES2024 Set methods
  (`union`, `intersection`, `difference`) but keep the runnable code portable.
- tuple → array. IMPORTANT: JS `Map`/`Set` use reference equality for arrays/objects, so when
  Python uses a tuple as a dict/set key (e.g. grid coords `(i, j)`), use a STRING key like
  `` `${i},${j}` `` instead.
- `collections.deque` → JS has no deque. For queues (BFS etc.), prefer an index-pointer over an
  array (push to add, read via a head index) to keep O(1) dequeue, and briefly note that
  `Array.prototype.shift` is O(n). A plain array with `push`/`shift` is acceptable for short prose
  examples; note the tradeoff once.
- `Counter` → count into a `Map`. `defaultdict(int/list/set)` → `Map` with a get-or-initialize
  pattern (helper or inline).
- `heapq` → JS has no built-in heap. Include a compact, correct `MinHeap` class (with `push`,
  `pop`, `peek`, `size`) in the chapter the first time a heap is needed, and use it. For a
  max-heap, negate values or pass a comparator. Explain the workaround like the original does.
- `sortedcontainers` (SortedList/SortedDict/SortedSet) → JS has no built-in sorted collection.
  Explain that, then implement with a sorted array + binary-search helpers (`bisectLeft`,
  `bisectRight`, insert via `splice`), giving working code. You may mention that production code
  would use a balanced-BST / library.

## Output
Write ONLY the final `.md` file to the target path using the Write tool. Do not ask questions —
make reasonable decisions. Your returned text should be a one-line confirmation, not the content.
